## 2\. 本次配置与排障流程简短总结

1. **原因定位**：

   * Antigravity 桌面端的后台服务 `language\_server.exe` 以及 VS Code 插件后台调用的 `C:\\Users\\hdq\\.gemini\\bin\\agy.exe --hub`（均为 Go 编译程序）不会读取 Windows 系统代理，导致只开系统代理+规则模式时无法连接。
2. **Antigravity 桌面端解决（`ide` 目录）**：

   * 采用开源项目 `yuaotian/antigravity-proxy` (v2.4)，将 `version.dll` 与 `config.json` 放入 `Antigravity.exe` 同级目录，通过进程创建 Hook 自动将子进程 `language\_server.exe` 流量转发至本机 `socks5://127.0.0.1:7890`（Bettbox 混合端口），交由规则模式分流。
3. **VS Code 插件解决（`cli` 目录）**：

   * 实测官方 Release 的 CLI 独立版（`dbghelp.dll` 劫持）会导致 `agy.exe` v1.4.9 启动卡死、健康检查超时。
   * 改用**宿主注入方案**：将桌面端同款 `version.dll` + 定制的 `config.json` 放入 VS Code 主程序目录（`E:\\Microsoft VS Code\\`），并在 `target\_processes` 中仅保留 `\["agy.exe", "language\_server.exe", "language\_server\_windows"]`，由 VS Code 启动插件后端时精准注入 `agy.exe`。
   * 将 `E:\\Microsoft VS Code\\config.json` 设为**只读属性**，防止被清理导致进入 BYPASS 模式。
4. **关闭弹窗提示**：

   * 在两份 `config.json` 中均加入 `"ui": { "load\_notify": "none" }`，彻底关闭每次启动时的加载成功提示弹窗。

## 3\. 日常维护注意事项

* **修改代理端口**：
默认连接 `127.0.0.1:7890`（`socks5`）。如果以后修改了代理软件端口，请修改目标目录（及本备份目录）下 `config.json` 中的 `"port": 7890`，重启软件生效。*(注：修改 `E:\\Microsoft VS Code\\config.json` 前需先右键属性取消“只读”，改完再勾回“只读”。)*
* **软件自动更新后失效**：
当 Antigravity 桌面端或 VS Code 大版本更新后，若发现又需要开 TUN 才能连上，直接把 `use\\ide` 或 `use\\cli` 下的两个文件重新复制覆盖到上述目标目录即可。
